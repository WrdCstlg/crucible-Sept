## Technical Post-Mortem & Architectural Rationale

While both candidates cleared the test suite with clean exit status (`Status: PASS | Exit Code: 0 | Duration: 0.0s`), raw terminal parity on a micro-test harness does not equate to production viability. The branches diverge sharply in algorithmic complexity, memory pressure, and data-structure ergonomics.

### The Winner: `branch_1` (Closed-Form State Machine)
* **Algorithmic Complexity:** $O(1)$ time and $O(1)$ heap allocations per event transition.
* **Mechanism:** Advances ticket state in-flight using closed-form business-minute modular arithmetic (computing calendar offsets and boundary intersections algebraically).
* **Systems Profile:** 
  * Zero heap churn: does not materialize transient structures or interval arrays.
  * Streaming-ready: state transitions execute sequentially in local cache/registers without requiring historical lookbacks.
  * Resilient against timeline fragmentation: compute cost remains strictly invariant regardless of the duration span or ticket lifecycle length.

### The Loser: `branch_2` (Event Sweep & Interval Reconstruction)
* **Algorithmic Complexity:** $O(N \log N)$ or $O(N)$ time per ticket with $O(N)$ dynamic memory allocations, where $N$ is the number of state mutations.
* **Mechanism:** Two-pass materialization pattern. It collects historical event boundaries, reconstitutes disjoint interval slices, and subsequently iterates through discrete time segments to count overlapping business minutes.
* **Systems Profile:**
  * **Allocation Amplification:** Dynamically instantiating interval tuples/slices introduces avoidable allocator overhead, pointer chasing, and garbage collection/fragmentation pressure.
  * **Scale Inefficiency:** Masked by the sub-millisecond execution (`Duration: 0.0s`) on small test fixtures, this approach degrades rapidly under pathological ticket lifecycles (e.g., automated systems flapping states across weeks).
  * **Anti-pattern:** Performing interval sweeps to solve a problem with an analytically deterministic, closed-form solution is structural waste.

---

## Architectural Directive

**`branch_1` is merged to trunk.** 

`branch_2` is discarded. Implementations that substitute closed-form math with intermediate structure allocations and iterative sweeps are strictly barred from high-throughput paths.
