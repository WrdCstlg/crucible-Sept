### THE RUTHLESS SYNTHESIS

#### 1. Why `branch_2` is Discarded (Architectural Flaw: Intermediate Allocation & Dual-Pass Inefficiency)
`branch_2` implements an **event-sweep model** that reconstructs running intervals into dynamic collections and then conducts a second aggregation pass to evaluate business minutes per interval.

* **Memory & Allocation Churn:** Materializing discrete interval objects creates unnecessary heap allocations and GC/deallocation overhead proportional to transition volume ($O(N)$ where $N$ is the number of ticket events). Under production scale (millions of ticket updates per day), this causes severe memory fragmentation and continuous cache-line invalidation.
* **Algorithmic Redundancy:** By splitting the problem into an *interval reconstruction phase* followed by an *interval integration phase*, `branch_2` traverses state boundaries twice. Handling business-hour boundary splits across reconstructed interval edges invites edge-case fragmentation and redundant modulo/calendar math across each slice.

#### 2. Why `branch_1` Survived (Operational Purity: Closed-Form Arithmetic via State Machine)
`branch_1` models the problem as an **inline, streaming state machine** operating with closed-form business-minute arithmetic.

* **Zero Intermediate Materialization:** It does not allocate transient interval arrays, records, or linked spans. The ticket maintains its internal timeline accumulator in-place.
* **$O(1)$ State Transitions:** When an event fires, the delta between the last transition and the current event is computed directly using closed-form calendar offsets (integer division and modulo operations over defined working shifts). State updates are immediate, deterministic, and cache-local.
* **Event-Driven / Stream Readiness:** This approach naturally integrates into a streaming or event-sourced pipeline (e.g., Kafka consumers or database write-ahead log triggers). It eliminates the requirement to reconstruct or hold the full historical event log in memory simply to calculate duration.

### FINAL VERDICT

* **Discard:** `branch_2` — Structural anti-pattern. Two-pass evaluation with transient interval allocation will not survive production throughput.
* **Adopt:** `branch_1` — Zero-allocation, stream-friendly, closed-form state machine. Immediate merge authorized.
