#### 2. Algorithmic Autopsy & Architectural Failure Analysis

* **`branch_2` (Event Sweep + Interval Reconstruction): REJECTED**
  * **The Structural Flaw:** `branch_2` introduces a multi-pass, state-materializing paradigm. By materializing every state change into explicit time intervals and subsequently sweeping those intervals to count business minutes, it incurs:
    1. **Heap Churn & Allocations:** Dynamic allocation of interval structures per ticket.
    2. **Algorithmic Inefficiency:** $O(N)$ interval generation followed by discrete or partitioned business-minute resolution, requiring intermediate synchronization of open/close boundaries.
  * While the execution log shows `Duration: 0.0s` due to minimal fixture sizes, this interval-rebuilding pattern collapses under production scale, inducing cache thrashing and memory pressure when ticket event counts scale into the millions.

* **`branch_1` (Per-Ticket State Machine with Closed-Form Arithmetic): WINNER**
  * **The Superior Design:** `branch_1` treats ticket lifecycle transitions as a streaming finite-state machine (FSM). 
  * Rather than reconstructing and storing intermediate interval objects, it computes business minutes elapsed between transitions using **closed-form arithmetic** directly at state entry and exit points.
  * **Algorithmic Complexity:** $O(1)$ auxiliary space and $O(1)$ time per transition. No intermediate interval vectors, no secondary passes, zero dynamic memory allocations on the hot path.
