## Ruthless Architectural Synthesis

### Why `branch_1` Fell Short
`branch_1` models the problem as an active, step-by-step state machine updated on every incoming event. While theoretically intuitive, this design suffers from fundamental mechanical sympathy flaws:
1. **Transition Churn Under Adversarial Ordering:** In the presence of out-of-order events (`test_out_of_order_events`) and malformed event streams (`test_malformed_lines_and_whitespace`), the state machine is forced to either perform costly event re-sorting per ticket or execute continual state rewinds/recomputations.
2. **Per-Event Call Overhead:** Updating state incrementally cell-by-cell (`test_state_machine_20_cells`) incurs continuous branch checking, timestamp boundary evaluations, and cache thrashing across disparate ticket contexts. This manifests directly in the measured latency penalty (**`0.057s`**).

### Why `branch_2` Survived
`branch_2` adopts an interval-reconstruction paradigm:
1. **Batch Interval Coalescing:** Instead of tracking micro-transitions on every event tick, `branch_2` isolates ticket streams, normalizes lifecycle bounds, and reduces the active durations into contiguous `[start, end]` intervals.
2. **Idempotent Arithmetic:** Summing resolved intervals simplifies the SLA calculation into pure arithmetic aggregation ($\sum (t_{\text{close}} - t_{\text{open}})$). This completely bypasses intermediate state thrashing, drastically reduces branch mispredictions, and maintains peak vectorization efficiency.
3. **Deterministic Boundary Handling:** When evaluating relative anchor points like `now` (`test_open_ticket_boundary_with_now`), interval clamping requires only a trivial boundary cap on the open right-hand interval, executing in constant time rather than traversing prior history.
